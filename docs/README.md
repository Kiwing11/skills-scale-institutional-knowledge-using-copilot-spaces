# OctoAcme Project Management Docs

This directory is the central reference for how OctoAcme plans, delivers, and improves cross-functional project work. Use these documents to understand the standard lifecycle, collaboration model, and operational practices that keep delivery predictable, transparent, and high quality.

OctoAcme project work starts with lightweight initiation and clear planning. Teams begin with a concise project one-pager that defines the problem statement, desired outcomes, and success metrics, then move into planning where scope is broken into shippable increments with explicit acceptance criteria and a Definition of Done. Backlog priorities, milestone mapping, and key artifacts are maintained in-repo to keep a shared source of truth for delivery decisions.

Execution is managed through a disciplined workflow that emphasizes visibility and quality gates. Teams progress work through a standard board flow (Backlog, Ready, In Progress, In Review, QA, Done), keep pull requests focused and traceable to issues, and require CI checks plus review approval before merge. Iteration planning, estimation, and dependency tracking support predictable cadence, while release and deployment practices include pre-release validation, smoke testing, rollback readiness, and post-deploy verification.

Roles and communication practices are structured to maintain ownership and alignment. Product Managers define outcomes and priorities, Project Managers coordinate schedules, risks, and cross-team execution, Developers implement and test, and QA validates acceptance criteria. Daily and weekly syncs, stakeholder updates, templates, and escalation paths provide consistent communication and risk handling across the lifecycle.

Continuous improvement is embedded in the process. Unit, integration, and critical-path smoke testing are expected where applicable, and CI/security scanning support baseline quality controls before release. Retrospectives after sprints, releases, or incidents capture action items with owners and due dates, feeding improvements back into planning so the system gets stronger over time.

## How to use these docs

- Start with the overview to understand shared principles, lifecycle stages, and artifacts.
- Use the process-specific guides for planning, execution, risk management, and release operations.
- Use roles/personas to clarify responsibilities when assigning work, approvals, and communications.
- Revisit retrospective guidance to capture learnings and convert them into backlog improvements.
